# PR 2 学习笔记：绘制清单、脏区和圆角 SDF

实现是 AI 辅助的。我定范围、审代码、跑 headless 测试。组件、布局、字形、命中测试这次没做。

## 这个 PR 干了什么

计划原文是：不把绘制写死在某一次 GPU 调用里，用一份中间清单描述圆角、描边和阴影，再用一个着色器画出来；脏区并成一块，交给剪刀。README 里这一步还点了 `FrameArena`、实例化合批。

现在仓库里有这些：

- `FrameArena`：这一帧的清单从缓冲区里拨指针分配。不够用时另开一块，旧块留到 `reset`，已经返回的切片在本帧内仍然有效。它还不放 UI 树。
- `DisplayList`：命令是 `quad`、`push_clip`、`pop_clip`、`glyph`。裁剪在记录时就和栈顶求交，结果记在 quad 上。
- `DamageRegion`：几个脏矩形并成一个。`null` 仍然表示整屏。
- `sdRoundedBox`：CPU 上的有向距离。点在圆角矩形里面是负数，外面是正数。片元着色器用同一公式。
- `QuadRenderer.paint`：同一裁剪的 quad 放进一个实例缓冲，一次 `SDL_DrawGPUPrimitives`。局部更新画在自己的离屏纹理上（`LOADOP_LOAD` + 剪刀），再把整张纹理贴到交换链。交换链是只写的，不能拿来存上一帧。片元着色器输出预乘颜色，源颜色混合系数是 `ONE`。

`glyph` 只占一个命令，不画。那是 PR 3。

## 一帧怎么走，变了什么

`AppLoop.drawOnce` 以前只清屏。现在如果挂了 `frame_build`：

1. 回调自己 `arena.reset()`，再往 `DisplayList` 里塞 quad。
2. 回调交回一个 `damage`。没有就整屏。
3. Headless 把清单收成批，记下 quad 数、批次数、要不要整屏清、剪刀有多大。
4. SDL 有 SPIR-V 时按批上传实例，画到一张持久纹理上，再整张贴到交换链。没有 SPIR-V 就整屏清交换链，并打错误日志。

demo 第一帧脏区是空的，整屏清，画出底板和一个圆角按钮。之后点击只把按钮的可视范围（含阴影那一圈）标成脏区，屏外像素留着。

## 关键取舍

- **没有组件树，就不自动算脏区。** 计划里的「这一帧真正变了的范围」需要上一帧的界面。那是 PR 5 的事。这次由调用方把矩形交进来，`DamageRegion.add` 负责并集。
- **裁剪不进模板缓冲。** 一把剪刀只能是一个矩形。裁剪一变就新开一批。这样仍然是实例化，但不是「500 个矩形永远一次 draw」。
- **GPU 一次最多 128 个 quad。** 多出来的这一帧丢掉并打日志。Headless 不设这个上限。
- **只提交 SPIR-V。** 这台 Linux 用 Vulkan。MSL 没生成，macOS 上这条管线可能创建失败，然后只清屏。
- **阴影和描边都看距离，不另造几何。** 网格比内容矩形大一圈（至少 1 像素，有阴影再加大），片元着色器在圈外画淡出去的阴影，在边缘画描边。

## 面试可能问的 5 个问题

1. **为什么要 DisplayList，不直接调 GPU？** 清单是普通数据，Headless 能数有几个 quad、分几批，不用开窗口。换 SDL 或以后的软件光栅，上层命令不用改。
2. **SDF 在这里干什么？** 圆角矩形不好用三角形硬切。给每个像素一个到边缘的距离：里面填色，贴着边缘的一圈是描边，外面按距离变透明就是阴影。一个着色器三种效果。
3. **实例化省了什么？** 顶点就 6 个，组成一个单位矩形。每个 quad 的位置和颜色是一份实例数据。同一批一次 draw，而不是一个矩形一次 draw。
4. **脏区和剪刀差在哪？** 脏区是「哪块内容变了」，在逻辑像素里并成一个矩形。剪刀是 GPU 真正允许写的像素范围，还要和裁剪矩形求交，再乘上缩放。`null` 脏区表示整屏清，避免半屏更新把旧背景留错。
5. **FrameArena 为什么不能拿来存回调？** 它每帧 `reset`。指针过一帧就作废。点击回调以后只能抓 `Entity` 这种跨帧句柄。`Entity` 还没做。
